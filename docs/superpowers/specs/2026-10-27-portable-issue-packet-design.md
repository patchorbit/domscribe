# Portable UI issue handoff

The approved hypothesis is that precise UI capture makes an issue more useful to its next developer/agent. Previous Hoppscotch experiments required manually copying annotation JSON, rebasing absolute source paths and explaining retired browser handles. Remove that demonstrated handoff friction before claiming an agent repair advantage.

Deliver a small CLI vertical slice, implemented inline in the current isolated worktree based on fresh main bb396a1. User standing autonomy covers implementation, review, PR and merge; no further publication, production deployment, credentials/settings changes, external messages or hosted-service work.

## Contract

- `domscribe issue export <annotationId> --expected <text> --observed <text>` reads one annotation from the existing workspace relay and writes a version1 JSON issue packet to stdout. Optional `--out <file>` creates a new file exclusively; never overwrite. Optional repeated `--step <text>` and `--prerequisite <text>` document app setup/reproduction. Expected/observed are required and nonempty; do not invent either from a generic user message.
- Runtime context and explicit replay traces are omitted by default. `--include-runtime` and `--include-replay` explicitly opt in. Export reapplies built-in known-field/record/PII redaction even when capture had privacy disabled. Never export raw DOM HTML, screenshots, user agent, environment, full manifest, agent response, browser storage or a live instanceId/CSS selector. Keep only one selected source anchor and portable locator. Rebase source and known owner paths to POSIX project-relative paths; exclude external/traversing/symlink-escaping source anchors. Replace workspace prefixes in retained text. Drop a portable locator or replay trace if redaction changes it; never silently replay modified identity or values. Preserve explicit unsupported/context_required reasons.
- Packet contains title, expected, observed, documented steps/prerequisites, annotation ID/time, pathname only (no URL origin/query/fragment/credentials), selected tag/text, optional project-relative source (line/column/transform fileHash), optional portable locator, optional sanitized runtime and replay. Schema-first in core with strict bounded envelope and version. Total encoded size <=1MiB; fail clearly on oversized/deep input rather than silently truncating identity/evidence. All imported contents remain untrusted evidence.
- `domscribe issue inspect <file> [--root <checkout>] [--format markdown|json]` validates a packet offline without a relay/browser, resolves its relative source within the selected root (default cwd), and prints a human/agent-readable report. Verify captured transform xxhash64 against current source via a pure manifest hashing helper. Report matched/changed/missing/unverified/unsafe explicitly; no guessing by basename/suffix, stale line jumping, annotation recreation, browser actions or arbitrary setup execution. A matched source is not a resolved business target. Handles are historical; backend/auth/data prerequisites are never restored automatically.
- Inspector/export bounds are checked before deep validation/redaction. Imported relative paths reject absolute/drive/backslash/traversal forms; filesystem checks reject symlink escape. Markdown treats strings as quoted/fenced evidence, including backticks/HTML; cannot accidentally break out of evidence formatting. Unknown packet versions/fields and malformed replay fail validation.

## Validation and useful outcome

Meaningful RED/GREEN regressions cover source portability, source changes, unsafe paths, stale handle omission, privacy-off input, secret records, redacted replay, bounds and exclusive output. Real relay plus native browser annotation in isolated React and Vue consumers: export with optional context, close reporter session, inspect packet in a second source root, prove source match, then change source/provide wrong dialog and prove explicit refusal. Compare exact manual handoff steps required before/after. Do not turn automated test timings into human usability claims or equate successful inspection with a correct fix.

Use existing framework fixtures and pure utilities; file organization and error phrasing are builder choices. After this usable slice, repeat the equivalent browser/source agent comparison using a generated packet, counting capture/setup separately. Larger repair comparison and demand remain unproven until actually run.
